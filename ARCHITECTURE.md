## Детальное описание уровней

### Уровень 1: Источники данных (Data Sources)

**Компоненты:**
- Приборы учёта (АСКУТЭ) - протоколы Modbus RTU/TCP, HTTP/REST
- Погодные сервисы (Росгидромет, OpenWeatherMap)
- Справочники (ФИАС, КЛАДР, реестр МКД)
- Внешние системы (ГИС ЖКХ, биллинг 1С)

**Адаптеры:**
- `backend/services/integrations/adapters/` - универсальный слой адаптации
- Конфигурируемые маппинги полей для гетерогенных протоколов
- Fallback-валидация при недоступности источников

### Уровень 2: Брокер сообщений и первичная валидация

**Технология:** RabbitMQ / Apache Kafka

**Топики/Очереди:**
| Топик | Назначение | QoS |
|-------|-----------|-----|
| `raw.metering` | Сырые данные с приборов | At-least-once |
| `raw.weather` | Погодные данные | At-most-once |
| `validation.failed` | Ошибки валидации (status=invalid) | At-least-once |
| `analytics.input` | Подготовленные данные для ML | Exactly-once |
| `audit.logs` | Журнал аудита действий | At-least-once |

**Первичная валидация:**
- Проверка целостности сообщения
- Базовая проверка диапазонов (min/max пороги)
- Дедепликация по timestamp + device_id

### Уровень 3: Хранение и обработка данных

#### Хранилища

**PostgreSQL 15+ с TimescaleDB:**
- Реляционные данные (справочники, пользователи, настройки)
- Временные ряды с партиционированием по времени и МКД
- Гипертаблицы для оптимизации запросов по временным диапазонам

**MinIO (S3-совместимое):**
- Сырые логи для аудита (неизменяемое хранение)
- Резервные копии конфигураций и моделей
- Архивы по ПП РФ №124 (сроки хранения ≥ 3 лет)

**Redis:**
- Кэш агрегатов и часто запрашиваемых данных
- Очереди Celery для фоновых задач
- Rate-limiting API endpoints
- Сессии пользователей

#### ETL/ELT конвейеры (Prefect)

**Пайплайн предобработки:**
1. **Синхронизация времени**
   - Приведение к единому часовому поясу (MSK/MCK)
   - Учёт переходов на летнее/зимнее время (исторические данные)

2. **Валидация данных**
   - Проверка статусов приборов по журналам событий
   - Детекция выходов за физические пределы
   - Флаги аномальных значений для последующей обработки

3. **Импутация пропусков**
   - ≤4 часа: линейная интерполяция
   - 4-12 часов: погодная импутация (регрессия на T_out)
   - >12 часов: регрессионная модель с лагами

4. **Feature Engineering**
   - Расчёт ГСОП по СП 50.13330.2012
   - Лаги температуры наружного воздуха (1-24 часа)
   - Скользящие статистики (среднее, дисперсия, min/max)
   - Флаги праздников, выходных, типов дней недели
   - Нормализация/стандартизация признаков

### Уровень 4: Аналитическое ядро и API

#### ML-модели

**Регрессионные модели:**
- `HuberRegressor` - робастная регрессия к выбросам
- `Ridge/Lasso` - регуляризация для мультиколлинеарности
- `QuantileRegressor` - прогноз интервалов (Q10, Q50, Q90)
- `pyGAM` - обобщённые аддитивные модели для нелинейностей

**Модели временных рядов:**
- `statsmodels SARIMA` - классические ARIMA с сезонностью
- `Prophet` - учёт календарных эффектов РФ (праздники, переносы)
- `pmdarima` - автоматический подбор параметров (p,d,q)(P,D,Q)

**Детекция аномалий:**
- `LOF (Local Outlier Factor)` - локальная плотность
- `Isolation Forest` - изоляция выбросов
- `EWMA` - экспоненциально взвешенное скользящее среднее
- `Bayesian Change Point Detection` - детектор сдвигов (ruptures)

**Кластеризация:**
- `K-means++` - базовая кластеризация МКД по профилям
- `DBSCAN` - поиск плотных областей, шум как аномалия
- `GMM (Gaussian Mixture Models)` - вероятностная кластеризация

**Консенсус-модуль:**
- Агрегация сигналов от множественных детекторов
- Пороговая логика по ПП РФ №354
- Взвешенное голосование с динамическими весами

#### FastAPI Backend

**Основные endpoints:**
| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/api/v1/ingest` | POST | Приём данных от источников |
| `/api/v1/analytics/{mcd_id}` | GET | Аналитика по МКД |
| `/api/v1/forecast/{mcd_id}` | GET/POST | Прогноз потребления |
| `/api/v1/anomalies` | GET | Список аномалий с фильтрами |
| `/api/v1/reports/{mcd_id}` | GET | Генерация отчётов (PDF/Excel) |
| `/api/v1/compliance/status` | GET | Нормативный статус МКД |
| `/api/v1/admin/users` | CRUD | Управление пользователями |

**Безопасность:**
- JWT/OAuth2 аутентификация
- RBAC (Role-Based Access Control)
- Аудит всех запросов и изменений
- Rate-limiting по IP и пользователю

## Инфраструктурные компоненты

### Контейнеризация и оркестрация

**Docker Compose (dev/staging):**
- Сервисы: postgres, timescaledb, minio, redis, rabbitmq
- Backend: fastapi app, celery worker, celery beat
- Frontend: nginx + react build
- Monitoring: prometheus, grafana, loki

**Kubernetes (production):**
- Deployment для stateless-сервисов
- StatefulSet для баз данных
- HorizontalPodAutoscaler по CPU/memory/queue depth
- NetworkPolicy для сегментации трафика

### CI/CD (GitHub Actions)

**Workflow:**
```yaml
lint → test → security-scan → build → push → deploy-staging → e2e → deploy-prod
```

**Этапы:**
1. **Lint**: ruff (Python), eslint (TypeScript), mypy (type check)
2. **Test**: pytest (unit/integration), playwright (e2e)
3. **Security**: bandit, safety, trivy (container scan)
4. **Build**: docker buildx multi-arch
5. **Deploy**: kubectl apply / helm upgrade

### Мониторинг и алертинг

**Prometheus + Grafana:**
- Метрики API: latency p50/p95/p99, error rate, RPS
- Метрики ML: inference time, model drift, prediction distribution
- Метрики DB: query time, connection pool, replication lag
- Метрики очередей: depth, consumer lag, retry rate

**Loki + Promtail:**
- Агрегация логов всех сервисов
- Structured logging (JSON format)
- Correlation ID для трассировки запросов

**Sentry:**
- Трекинг ошибок frontend/backend
- User context, breadcrumbs, session replay
- Алерты в Telegram/Email/Slack

## Соответствие нормативным требованиям РФ

### ПП РФ №354 (Правила предоставления коммунальных услуг)
- Расчёт нормативов потребления
- Классификация статусов эффективности
- Формирование отчётов для собственников

### ПП РФ №124 (Правила учёта ресурсов)
- Требования к приборам учёта
- Сроки хранения данных (≥3 лет)
- Процедуры поверки и калибровки

### СП 50.13330.2012 (Тепловая защита зданий)
- Расчёт ГСОП (градусо-сутки отопительного периода)
- Нормативные значения удельного расхода
- Методики оценки энергоэффективности

### ГИС ЖКХ (Приказ Минкомсвязи №774)
- Форматы экспорта XML/JSON
- Схемы валидации XSD
- Регламент обмена данными

### ФСТЭК России
- Шифрование каналов связи (TLS 1.3, ГОСТ при необходимости)
- Разграничение прав доступа (RBAC)
- Неизменяемость аудит-логов
- Локализация данных на территории РФ

## Масштабируемость и производительность

**Горизонтальное масштабирование:**
- Stateless backend → автодобавление pod'ов
- Partitioned TimescaleDB → шардирование по МКД
- Kafka consumer groups → параллельная обработка

**Вертикальная оптимизация:**
- Async I/O (FastAPI, SQLAlchemy async)
- Connection pooling (PgBouncer, Redis pool)
- Query optimization (индексы, materialized views)

**Целевые показатели:**
- Поддержка ≥10,000 МКД
- Latency API <100ms (p95)
- Throughput ingestion ≥50,000 msg/sec
- Availability ≥99.9%
